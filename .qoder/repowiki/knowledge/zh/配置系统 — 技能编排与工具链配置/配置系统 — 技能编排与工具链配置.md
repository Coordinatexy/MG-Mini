本仓库是一个以 AI Agent 技能编排为核心的原型工作流项目，**不包含传统意义上的运行时应用配置系统**（如 .env、application.properties、YAML/ TOML 服务配置等）。其“配置”主要体现在以下两个层面：

1. **技能 API 全局配置**：`.agents/skills/config.json` 集中定义了所有技能脚本可调用的外部 API 基地址与超时等参数（如 `apiBaseUrl`、`diagramApiUrl`、`timeout`），由导出脚本和图表渲染工具读取。该文件是跨技能的唯一共享配置源。

2. **脚本级运行配置**：截图脚本 `.agents/skills/pm-operation-manual/scripts/screenshot.js` 通过命令行参数 `--config <path>` 接收一个 JSON 配置文件（如 `screenshot-plan.json`），用于指定目标站点 baseUrl、输出目录、登录凭据、页面列表、视口尺寸等。该脚本会按优先级自动检测 Playwright / Puppeteer / puppeteer-core 三种浏览器驱动，并据此调整启动参数。

此外，AGENTS.md 中提到的 `.agents/skills/common/export-word.*`、`render-diagram.*` 等脚本也遵循相同的“JSON 配置文件 + 命令行参数”模式，但具体字段由各脚本自行定义，没有统一的 schema 或加载器。

**约束与约定**：
- 所有外部 API 地址统一收口在 `.agents/skills/config.json`，避免硬编码 URL。
- 截图类脚本必须通过 `--config` 传入配置文件路径，不支持环境变量注入。
- 未显式声明的配置项使用脚本内默认值（如 screenshot.js 中 baseUrl 默认为 `http://localhost:5173`）。
- 无 secrets 管理、无多环境切换机制、无配置热重载。

由于本项目本质是静态原型生成与文档编排工具集，而非可部署的后端服务，因此不存在运行时配置加载、分层覆盖、feature flag 等典型配置系统能力。
