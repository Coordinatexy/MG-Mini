## 架构总览
主反馈页面采用“控制器 + Store”的轻量 MVC 模式：
- 控制器负责 UI 行为与流程编排
- Store 负责数据与状态
- 通过事件驱动更新视图，避免直接耦合 DOM 与业务逻辑

```mermaid
sequenceDiagram
participant U as "用户"
participant V as "视图(HTML/CSS)"
participant C as "控制器(function-feedback.js)"
participant S as "状态(反馈-store.js)"
participant API as "后端接口"
U->>V : "打开页面/点击按钮"
V-->>C : "触发事件(新增/编辑/删除/搜索/分页)"
C->>S : "读取/更新状态"
C->>API : "发起请求(增删改查/批量)"
API-->>C : "返回结果或错误"
C->>S : "持久化结果到状态"
C->>V : "渲染列表/提示消息"
```

## 详细组件分析

### 列表渲染机制
- 数据源
  - 从 Store 获取当前页数据与分页元信息
- 渲染策略
  - 基于模板生成节点，优先复用已有节点，减少重排重绘
  - 对空态、加载中、错误态分别渲染占位与提示
- 性能优化
  - 使用 DocumentFragment 批量插入
  - 事件委托至容器，避免为每个条目绑定事件
  - 按需渲染（虚拟滚动可选）

```mermaid
flowchart TD
Start(["开始渲染"]) --> LoadData["从 Store 获取数据"]
LoadData --> CheckState{"是否有数据?"}
CheckState --> |否| RenderEmpty["渲染空态/提示"]
CheckState --> |是| BuildNodes["构建节点片段"]
BuildNodes --> InsertNodes["批量插入 DOM"]
InsertNodes --> BindEvents["事件委托绑定"]
BindEvents --> End(["完成"])
```

## 故障排查指南
- 常见问题
  - 列表不更新：检查 Store 是否被正确更新与触发渲染
  - 表单校验无效：检查校验规则与错误聚合展示
  - 接口报错：查看错误分类与日志输出
  - 事件失效：检查事件委托目标与动态节点绑定
- 调试建议
  - 在关键路径添加断点与日志
  - 使用浏览器 Network 面板检查请求与响应
  - 使用 Performance 面板分析渲染耗时
