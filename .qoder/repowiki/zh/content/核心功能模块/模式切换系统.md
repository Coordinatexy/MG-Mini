## 架构总览
模式切换系统采用“数据驱动 + 事件驱动”的轻量架构：
- 数据层：模式定义与当前状态
- 控制层：切换逻辑与校验
- 视图层：DOM 渲染与交互反馈
- 存储层：本地持久化（可选）
- 事件层：模式变更广播与订阅

## 详细组件分析

### 模式数据模型
- 模式标识：唯一 ID，用于定位与持久化
- 模式元信息：名称、图标、描述、排序权重
- 行为标志：是否可切换、是否默认、是否受权限限制
- 扩展字段：不同模式可能携带额外配置（如颜色主题、布局开关）

建议的数据流：
- 初始化时加载模式清单
- 根据当前状态选择高亮项
- 切换时校验行为标志并更新视图

- [function-mode.js](file://app/js/function-mode.js)

### 状态管理器
职责：
- 维护当前模式、历史栈、切换锁
- 提供 get/set 接口与校验逻辑
- 支持撤销/重做（可选）
- 触发持久化与事件广播

### UI 控制器
职责：

交互要点：
- 点击后立即锁定，防止重复切换
- 切换失败时恢复解锁并给出明确提示

### API 参考（概念性）
- 获取当前模式
  - 输入：无
  - 输出：当前模式 ID
  - 异常：未初始化时抛出错误
- 检查是否可切换
  - 输入：目标模式 ID
  - 输出：布尔值
  - 异常：非法 ID 时抛出错误
- 执行切换
  - 输入：目标模式 ID
  - 输出：Promise（成功/失败）
  - 异常：切换失败时返回错误原因
- 订阅模式变更
  - 输入：回调函数
  - 输出：取消订阅函数
  - 异常：无效回调时忽略

## 性能考虑
- 避免频繁 DOM 操作：批量更新节点，减少重排与重绘
- 切换锁与节流：防止高频点击导致多次切换
- 懒加载与按需渲染：仅渲染可见模式项
- 事件去抖：对搜索或过滤场景进行防抖处理
- 持久化优化：合并写入与异步落盘

## 故障排查指南
- 现象：点击模式无响应
  - 排查：确认 DOM 已就绪、事件绑定是否生效、是否有切换锁
  - 解决：延迟绑定或在 ready 钩子中初始化
- 现象：切换后视图未更新
  - 排查：事件总线是否正确广播、订阅是否注册
  - 解决：确保 emit/on 成对出现，检查事件名一致性
- 现象：切换失败但无提示
  - 排查：错误分支是否调用 showFeedback
  - 解决：统一错误处理与用户提示
- 现象：状态不一致
  - 排查：持久化是否成功、历史栈是否越界
  - 解决：增加重试与边界检查
